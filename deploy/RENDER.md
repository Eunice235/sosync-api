# Hosting SOSync on Render + Neon

Free, no card, no server to manage. Render runs the API from this GitHub repository; Neon holds
the database. Takes about 20 minutes, most of it Render's first build.

## 1. Database (neon.tech)

1. Sign up with GitHub, create a project named `sosync`. Pick the region closest to your
   Render region (e.g. *AWS Europe (Frankfurt)*).
2. On the project dashboard, click **Connect**. Note three things from the connection details:
   - **Host**, e.g. `ep-cool-name-123456.eu-central-1.aws.neon.tech`
   - **Database**, usually `neondb`
   - **Role** and **Password**

Build the database address from them:

```
jdbc:postgresql://<Host>/<Database>?sslmode=require
```

The app creates its own tables on first start. There is nothing to run in Neon.

## 2. API (render.com)

1. Sign up with GitHub and allow Render to see the `sosync-api` repository.
2. **New → Blueprint**, choose `sosync-api`. Render reads `render.yaml` and proposes one free
   web service.
3. It asks for the values marked secret:

| Key | Value |
|---|---|
| `DB_URL` | the `jdbc:postgresql://…?sslmode=require` address from step 1 |
| `DB_USERNAME` | the Neon **Role** |
| `DB_PASSWORD` | the Neon **Password** |
| `SOSYNC_DEMO_PASSWORD` | a password of your own for the demo accounts (Amina, Daniel…) |

`SOSYNC_JWT_SECRET` is generated by Render automatically.

4. **Apply**. The first build takes 5–10 minutes. When the log shows `Started SosyncApplication`,
   open `https://<your-service>.onrender.com/actuator/health`. It should say `"status":"UP"`.

The address is on the service's page, top left, e.g. `https://sosync-api.onrender.com`.

## 3. Keep it awake (uptimerobot.com)

A free Render service sleeps after 15 minutes without requests, and takes about a minute to
wake — longer than the app waits. During testing and the demo, keep it awake:

**Add New Monitor → HTTP(s)**, URL `https://<your-service>.onrender.com/actuator/health`,
interval **5 minutes**.

## 4. Point the app at it

In `mobile/lib/config.dart`:

```dart
static const String serverAddress = 'https://<your-service>.onrender.com';
```

Then build the APK to share:

```bash
cd mobile && flutter build apk --release
```

The file is `mobile/build/app/outputs/flutter-apk/app-release.apk`. Anyone who used the
**Change** link on an earlier build should uninstall it first, or the saved address wins.

## Updating

Push to `main` on GitHub. Render rebuilds and redeploys by itself.

## If something goes wrong

| What you see | What it means |
|---|---|
| Build log: `gradlew: not found` or `permission denied` | Line endings; the Dockerfile fixes these, so check that `backend/Dockerfile` was pushed |
| Log: `Connection to … refused` or `password authentication failed` | `DB_URL`, `DB_USERNAME` or `DB_PASSWORD` is wrong. Check `?sslmode=require` is on the end |
| Log: `Exit status 137` or `OutOfMemoryError` | The free instance ran out of memory. Redeploy once; if it repeats, tell whoever maintains this |
| App: *server did not answer in time* | The service was asleep. Open the health address in a browser, wait a minute, retry, and set up step 3 |
